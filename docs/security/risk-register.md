## Secret review and logging

`.env` and local overrides are ignored. Root/client `.env.example` contain safe placeholders; tracked `client/.env.production` contains only a public API URL. A targeted pattern scan of 95 tracked files and 223 reachable history blobs checked private-key markers, credentialed MongoDB URIs, selected provider-token formats and JWT-shaped strings. One match in tracked `server_out.log:1` has a `***` password, not a live credential. No confirmed exposed credential was found by this limited scan and none was rotated. This is not a full entropy/secret scan or proof of absence; unreachable remote history and deployed environment/bundle contents were not comprehensively scanned.

`server_out.log` and `server_err.log` are still tracked despite ignore patterns. They contain operational metadata and should be untracked in a narrow future cleanup after review. Do not publish raw logs, environment dumps, ID tokens, account data or unredacted scan matches in future reports. `connectDb.js` prints masked connection metadata and raw database error text; redaction should become structured and tested.

## Reproduction and scope boundaries

`node scripts/audit-phase0.cjs` starts disposable MongoDB, seeds only synthetic users/records and prints observations (see `docs/audit/phase0-baseline.json`). Direct foreign-user transaction GET/PUT/DELETE all returned 404, a useful existing guard, while reporting metadata isolation failed. Script success means the observations ran, **not** that correctness gates passed. Convert relevant observations into failing-then-fixed regression tests in the next phase.

Google exchange is covered by mock-provider integration tests; real verifier rejects forged tokens. The prior deployed browser sign-in succeeded earlier in this chat. The old Google HTTP 500 was not reproduced during this audit and no historical stack trace is available. Interactive local Google auth, concurrent first login, provider/network outages and full server CORS/session behavior remain unverified. Missing-email Google identities currently return 401 by design; decide the product contract before relaxing it.

Phase 0 stops here. No production data mutation, auth/session migration, schema change, dependency upgrade, paid service, rotation or later-phase implementation was performed. The next prompt should authorize Phase 1 with the P1 security findings as acceptance criteria.
