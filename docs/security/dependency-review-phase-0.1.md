# Dependency security review — Phase 0.1

18 October 2026. Exact installed versions/lockfiles checked with npm 11.19.0 and Node 24.21.0. Full advisory/path inventory and lockfile version changes are in `dependency-review-phase-0.1.json`. This is risk triage, not a certification.

## Tools and observations

Commands: `npm ls --depth=0`, `npm ls --prefix client --depth=0`, `npm outdated --json`, `npm outdated --prefix client --json`, `npm audit --json`, `npm audit --omit=dev --json`, `npm audit --prefix client --json`, and targeted `npm explain` for mock-mongoose, proxy-addr, lodash, path-to-regexp, underscore, Firebase and webpack-dev-server. Raw outputs were retained in task scratch space; reports contain no credentials or financial records.

| backend | 5/8/12/1 | 0/0/0/0 | Counts include advisory inheritance/tooling, not independent demonstrated exploits. |
| client | 4/84/16/6 | 0/67/15/5 | Counts include advisory inheritance/tooling, not independent demonstrated exploits. |

Root `--omit=dev` audit also has zero known findings at scan time. That does not establish zero vulnerabilities. Frontend deployment emits static assets; npm classification alone incorrectly suggests all CRA tooling runs in production because react-scripts is under dependencies. We did not reclassify packages just to reduce counts.

## Supply chain and compatibility notes

Official maintainer release/changelog pages consulted alongside registry/audit results: [Express](https://github.com/expressjs/express/releases), [Mongoose](https://github.com/Automattic/mongoose/blob/master/CHANGELOG.md), [Axios](https://github.com/axios/axios/releases), [React Router](https://reactrouter.com/changelog). Dependency audit advisories are linked individually above.

Unused frontend chart.js/react-chartjs-2/date-fns/direct Tailwind declarations are cleanup candidates based on source search, not removed blindly: CRA has its own toolchain dependencies. React/Redux/Ant Design/charting upgrades are deferred unless a concrete reviewed advisory requires them. Prettier was used as a temporary registry formatting CLI only, not added as an application dependency. No security tool or GitHub protection was disabled.

Run the exact CI-equivalent tests/build after any subsequent remediation; re-audit counts rather than relying on this snapshot. A zero known backend audit is not a reason to skip authorization, session-storage or code review.
